# Monitoring Dashboard & RAG Export

**Date:** 2026-05-02
**Status:** Approved

---

## 1. Goal

Add two capabilities to the scrapper:
1. **Monitoring dashboard** — persist crawl metrics and generate a local HTML dashboard after each run, without external services or VPS.
2. **RAG-ready export** — output scraped items as Markdown (with YAML frontmatter) and JSON Lines chunks optimized for vector DB ingestion (ChromaDB, pgvector, Pinecone).

## 2. Non-Goals

- Adding a server, VPS, or external monitoring service (ScrapydWeb, ScrapeOps)
- Real-time streaming or websockets for the dashboard
- Changing the Supabase pipeline or spider extraction logic
- Adding new dependencies — everything uses stdlib or existing packages

## 4. Metrics Persistence

### 4.1 StatsLogger modification

Extend `StatsLogger` to persist a JSON record after logging. Constructor now accepts `metrics_dir` and `metrics_max_runs` read from Scrapy settings in `from_crawler`. `spider_opened` unchanged.

**File:** `src/scrapper/extensions.py`

**Output:** `metrics/metrics.json`

**Schema:**
```json
{
  "runs": [
    {
      "spider": "reddit",
      "started_at": "2026-05-03T00:54:32+00:00",
      "finished_at": "2026-05-03T00:54:38+00:00",
      "status": "finished",
      "reason": "finished",
      "items": 10,
      "responses": 1,
      "errors": 10,
      "elapsed_seconds": 5.5,
      "rate_per_minute": 109.9
    }
  ]
}
```

- `from_crawler` now reads `METRICS_DIR` and `METRICS_MAX_RUNS` from settings and passes them to constructor
- `__init__(self, metrics_dir, metrics_max_runs)` — stores both for use in `spider_closed`
- Timestamps: ISO 8601 with timezone (UTC)
- `status`: maps Scrapy close reason to `finished` / `cancelled` / `failed`
- `rate_per_minute`: `items / elapsed_seconds * 60`, 0 if elapsed is 0
- Directory `metrics/` created automatically on first write
- Configurable retention: `METRICS_MAX_RUNS` (default 100 per spider). Oldest entries pruned on append.

### 4.2 Settings additions

```python
METRICS_DIR = "metrics"
METRICS_MAX_RUNS = 100
```

## 5. Metrics Dashboard

### 5.1 MetricsDashboard extension

**File:** `src/scrapper/dashboard.py`

Connects to `spider_closed` signal. After each crawl, reads `metrics/metrics.json` and regenerates `metrics/dashboard.html`.

Class:
```python
class MetricsDashboard:
    def __init__(self, metrics_dir: str):
        self.metrics_dir = metrics_dir

    @classmethod
    def from_crawler(cls, crawler):
        ext = cls(metrics_dir=crawler.settings.get("METRICS_DIR", "metrics"))
        crawler.signals.connect(ext.spider_closed, signal=signals.spider_closed)
        return ext

    def spider_closed(self, spider, reason):
        self._build_dashboard()
```

### 5.2 Dashboard content

Single self-contained HTML file. No external CSS/JS libraries. Data embedded as `<script>` tag.

| Section | Content |
|---------|---------|
| **Summary cards** | Total runs, total items scraped, success rate (%), unique spiders |
| **Runs table** | Per spider: date, items, errors, duration, status. Sortable by column. |
| **Error rate chart** | Horizontal bar chart (CSS-rendered) showing error % per spider |
| **Items trend** | Simple sparkline-style bar chart of items per run (last 10 runs per spider) |

**Visual design:**
- Dark theme, monospace font, minimal
- Cards at top with key numbers in large text
- Table below with sortable columns (click header to sort)
- Charts rendered with CSS `width` percentages — no canvas/SVG needed for bar charts
- Responsive: works on mobile

### 5.3 Data embedding

```html
<script>
const METRICS = {"runs": [...], "generated_at": "2026-05-03T00:55:00Z"};
</script>
```

All rendering done by inline vanilla JS that reads `METRICS` and builds DOM.

## 6. RAG Export Pipelines

### 6.1 MarkdownExportPipeline

**File:** `src/scrapper/rag_export.py`

Converts each item to a `.md` file with YAML frontmatter. Uses `open_spider` to create output directory and initialize collision counter; `close_spider` for cleanup.

**Output path:** `rag_output/{site}s/{site}-{slug}.md`

- Directory created automatically on first write (via `open_spider`)
- Slug generated by reusing `slugify()` from `src/scrapper/utils.py` (lowercase, alphanumeric + hyphens, max 80 chars, truncate at word boundary)
- Collision check: if file already exists on disk (from a previous run), append `-2`, `-3`, etc.
- Collision counter resets per run but checks existing files across all runs

**Format:**
```markdown
---
site: reddit
url: https://old.reddit.com/r/...
title: "How I learned Python"
author: r/PythonLearning
score: 146
comments: 231
scraped_at: 2026-05-03T00:54:35+00:00
source_type: social_media
---
# How I learned Python

I spent the last year learning Python and producing an animated Discord bot...
```

- `source_type` maps spider name to `social_media` (Reddit) or `product_listing` (Hotmart)
- Content field becomes the body. If content is `None` or empty string, body is just the title as H1.
- YAML frontmatter values: `None` becomes empty string, strings with special chars are quoted per YAML 1.2
- Pipeline uses `open_spider`/`close_spider` to manage output directory and collision counters

### 6.2 ChunkedJSONPipeline

**File:** `src/scrapper/rag_export.py`

Appends one JSON object per line to `rag_output/chunks.jsonl`.

**Format:**
```json
{"chunk_id": "reddit-1obwkbb", "text": "# How I learned Python\n\nI spent the last year...", "metadata": {"site": "reddit", "url": "https://...", "title": "How I learned Python", "author": "r/PythonLearning", "score": 146, "comments": 231, "scraped_at": "2026-05-03T00:54:35+00:00", "source_type": "social_media"}}
```

- `chunk_id`: `{site}-{hashlib.sha256(url.encode()).hexdigest()[:8]}`
- `text`: Markdown-rendered item (same as .md file body, with title as H1)
- `metadata`: all item fields except content (content goes in `text`)
- Pipeline opens file handle in `open_spider` and closes in `close_spider` — appends one line per `process_item` call
- JSON is compact (no extra whitespace) — one object per line, no trailing comma

### 6.3 Activation

Both pipelines controlled by settings:

```python
RAG_EXPORT_ENABLED = os.getenv("RAG_EXPORT_ENABLED", "true").lower() in ("true", "1", "yes")
RAG_OUTPUT_DIR = "rag_output"
```

Pipeline registration (conditionally enabled):
```python
if RAG_EXPORT_ENABLED:
    ITEM_PIPELINES["scrapper.rag_export.MarkdownExportPipeline"] = 400
    ITEM_PIPELINES["scrapper.rag_export.ChunkedJSONPipeline"] = 450
```

- `test_markdown_export_creates_file`: feed a PostItem, verify `.md` file created with frontmatter
- `test_markdown_slug_from_title`: verify "How I Learned Python!" → `how-i-learned-python` (reuses `slugify` from utils)
- `test_markdown_content_none_handled`: verify item with `content=None` does not crash, body is title
- `test_markdown_slug_collision`: verify existing file → `-2` suffix on new file in same run
- `test_jsonl_appends_lines`: feed two items, verify file has two JSON lines
- `test_jsonl_uses_open_spider_close_spider`: verify file handle opened once, not per-item
- `test_chunk_id_format`: verify `chunk_id` is `{site}-{8 hex chars from sha256}`
- `test_rag_disabled_by_env`: mock `RAG_EXPORT_ENABLED=false`, verify pipelines don't execute
